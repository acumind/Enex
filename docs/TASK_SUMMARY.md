## Observations & Decisions Made During Sprint 0

### 1. Node.js version bump: 18 -> 20

The plan specified Node 18 for the CI and Dockerfile, but **Next.js 16.x (latest as of create-next-app) requires Node >= 20.9.0**. Both the Dockerfile and CI workflow were updated to use Node 20. Future sprints should use Node 20+ everywhere.

### 2. Next.js version is 16.x, not 15

Running `create-next-app@latest` installed **Next.js 16.1.6** (with React 19.2.3). This is the current latest stable. The plan was written when Next.js 15 was current. This is fully backwards-compatible — App Router, RSC, standalone output all work the same way.

### 3. Tailwind CSS v4 (not v3)

Shadcn/ui now initializes with **Tailwind CSS v4**, which uses CSS-first configuration instead of `tailwind.config.ts`. The `globals.css` file contains all theme configuration via `@theme` directives. No `tailwind.config.ts` file exists — this is intentional with v4.

### 4. Alembic auto-generated migration excluded from linting

The auto-generated migration file uses old-style `Union[str, None]` types, long lines, and unsorted imports. Rather than manually reformatting (which would break on future auto-generates), `migrations/versions/` is excluded from ruff via `extend-exclude`. This is the standard practice.

### 5. FastAPI `Depends()` B008 suppression

Ruff rule B008 flags `Depends()` calls in default arguments. This is an intentional FastAPI pattern, so `app/api/**` files have `B008` suppressed via `per-file-ignores`.

### 6. MyPy strict mode — third-party overrides needed

Several libraries lack complete type stubs: `celery`, `jose`, `passlib`, `yfinance`, `redis`. These are configured with `ignore_missing_imports = true` in `[[tool.mypy.overrides]]`. As the project grows, consider adding `types-redis` and other stub packages.

### 7. SQLAlchemy JSONB columns — generic type annotations

JSONB columns (`social_links`, `auth_methods`, `sector_accuracy`, `data`) use typed generics like `Mapped[dict[str, str]]` and `Mapped[list[str]]` to satisfy mypy strict mode. The actual JSON stored can be more flexible, but the type hints provide baseline safety.

### 8. Python 3.13 used locally (3.12 targeted)

`uv` resolved to Python 3.13.3 locally, while `pyproject.toml` targets `>=3.12` and CI uses 3.12. This is fine — 3.13 is a superset. The Dockerfile pins `python:3.12-slim` for production consistency.

### 9. `upside_pct` generated column not in ORM

The SQL schema defines `upside_pct` as a `GENERATED ALWAYS AS` stored column on the `predictions` table. SQLAlchemy's Alembic autogenerate does not emit this — it would need a manual `op.execute(ALTER TABLE ...)` in a future migration if this computed column is desired at the DB level. For now, this can be computed in the application layer.

### 10. Azure deployment deferred

Dockerfiles are ready but actual Azure Container Apps provisioning requires Azure subscription setup, ACR creation, Key Vault configuration, and managed identity. This is an operational step outside Sprint 0 scope.

## Developer Quick Reference

### Local Development Workflow

```bash
# 1. Start infrastructure
docker compose up -d

# 2. Backend
cd backend
uv sync                              # install/update deps
uv run alembic upgrade head          # apply migrations
uv run uvicorn app.main:app --reload # start dev server (:8000)

# 3. Frontend (separate terminal)
cd frontend
npm install                          # install/update deps
npm run dev                          # start dev server (:3000)

# 4. Run checks
cd backend && uv run ruff check . && uv run mypy . && uv run pytest -v
cd frontend && npm run lint && npx tsc --noEmit
```

### Key URLs (local dev)

| Service | URL |
|---------|-----|
| Backend API | http://localhost:8000 |
| Swagger UI | http://localhost:8000/docs |
| Health check | http://localhost:8000/api/v1/health |
| Frontend | http://localhost:3000 |
| PostgreSQL | localhost:5432 (user: `enex`, pass: `dev_password`, db: `enex`) |
| Redis | localhost:6379 |

### Creating New Alembic Migrations

```bash
cd backend
# After modifying models:
uv run alembic revision --autogenerate -m "describe_the_change"
# Review the generated file in migrations/versions/
uv run alembic upgrade head
```

### Adding a New API Endpoint

1. Create/update Pydantic schemas in `app/schemas/`
2. Create service logic in `app/services/`
3. Create repository (DB queries) in `app/repositories/`
4. Create route in `app/api/routes/`
5. Register the router in `app/main.py`
6. Add tests in `tests/`

### Adding Shadcn/ui Components

```bash
cd frontend
npx shadcn@latest add button    # example: adds Button component
npx shadcn@latest add card      # adds Card component
# Components land in components/ui/
```

## Upcoming Sprints — What to Know Before Starting

### Sprint 1: Core Data Layer

**Scope:** CRUD APIs for predictors, stocks, predictions + admin user management + stock seeding.

**Prerequisites from Sprint 0:**
- All models already exist — no new migrations needed for core tables
- The layered architecture skeleton (`services/`, `repositories/`, `api/routes/`) is ready
- Health endpoint demonstrates the pattern to follow for new routes

**Key implementation decisions:**
- `require_role()` FastAPI dependency for admin/moderator guards — implement in `app/core/auth.py`
- Repository pattern: one repository class per model with async CRUD methods
- Service layer handles business logic (validation, authorization checks)
- Use `app/schemas/` for all request/response Pydantic models (not the ORM models directly)
- Stock seeding: create a CLI command (`python -m app.cli seed-stocks`) that loads NSE top 200 from a CSV or API
- Slug generation for predictors: use `python-slugify` or a simple `name.lower().replace(" ", "-")` utility
- `create-admin` CLI: `python -m app.cli create-admin --email admin@enex.in`

**Watch out for:**
- The `predictors` table has a self-referencing `parent_id` FK — ensure the API handles this (individuals linked to firms)
- `users.email` and `users.phone` are both nullable, but the `user_has_identity` CHECK constraint requires at least one
- The admin role assignment endpoint should prevent the last admin from being demoted

### Sprint 2: Prediction Entry & AI Assist

**Scope:** AI extraction from URLs, prediction submission flow, suggestion system, bulk import.

**Key integration points:**
- `app/integrations/` is where Anthropic Claude adapter goes — use Protocol + Adapter pattern per ARCHITECTURE.md
- Claude extraction: send article text to Claude Sonnet, get structured prediction JSON back
- Implement `app/integrations/ai/protocol.py` (ABC) + `app/integrations/ai/anthropic_adapter.py`
- Source archival: Wayback Machine Save API (`web.archive.org/save/{url}`) — implement in `app/integrations/archival/`
- Duplicate detection: query by (predictor_id, stock_id, target_price within 5%, prediction_date within 7 days)

**Watch out for:**
- Claude API prompt injection via user-submitted URLs — sanitize and limit input tokens (`ANTHROPIC_MAX_INPUT_TOKENS=8000`)
- The review queue is critical — **no prediction goes live without moderator approval**
- Bulk import should use Celery for background processing, not synchronous API calls

### Sprint 3: Evaluation Engine

**Scope:** Daily job that compares predictions to actual prices and computes outcomes.

**Key implementation points:**
- Celery worker uses the same Docker image, different entrypoint: `celery -A app.jobs.celery_app worker`
- Price fetcher job: `yfinance` to download daily OHLCV data for tracked stocks
- Evaluation job: runs daily, finds approved predictions past their `default_eval_date`, computes hit/miss/partial
- Scorecard materialization: aggregate stats per predictor, store in `predictor_scorecards`
- The tolerance band logic is defined in `docs/ROLLOUT_PLAN.md` — follow exactly

**Watch out for:**
- Stock splits/bonuses affect price comparison — use `adjusted_close` from `stock_daily_prices`
- `yfinance` uses `.NS` suffix for NSE stocks (e.g., `RELIANCE.NS`) — handle this in the price data adapter
- Weekend/holiday handling: if `eval_date` falls on a non-trading day, use the nearest prior trading day

### Sprint 4: Public Interface

**Scope:** SSG/ISR pages for leaderboard, predictor profiles, stock pages, search.

**Key frontend patterns:**
- Leaderboard: Server Component with ISR (revalidate every 5–10 minutes)
- Predictor profiles: dynamic route `[slug]` with `generateStaticParams` for popular predictors
- Use TanStack Query for client-side data fetching on interactive pages
- Zustand for client state (filters, sort preferences, theme)
- Recharts or Tremor for accuracy trend charts

**Watch out for:**
- SEO is critical for this sprint — every predictor profile needs proper `<title>`, `description`, and OpenGraph tags
- The `predictor_scorecards` table must have `total_predictions >= 10` for the accuracy index — handle "insufficient data" display
- Pagination: use cursor-based pagination (not offset) for prediction lists to avoid performance issues at scale

### Sprint 5: User Features & Auth

**Scope:** Three auth paths (Google OAuth, Email OTP, Phone OTP), user engagement features.

**Key implementation points:**
- NextAuth.js v5 handles Google OAuth on the frontend side — backend receives the JWT
- Email/Phone OTP: backend generates OTP, stores hashed in `otp_codes`, sends via Resend/MSG91
- OTP verification returns backend JWT (not NextAuth session) — the backend is the authority
- Rate limiting: Redis-backed counters per identifier (email/phone), enforced in middleware

**Watch out for:**
- Account linking: if a user logs in with Google and later with phone OTP, match by email to merge accounts
- The `otp_codes` table stores hashed codes — use `passlib` bcrypt for hashing
- MSG91 requires DLT registration for Indian SMS — this is a regulatory setup step, not a code task
- JWT refresh token rotation: issue new refresh token on each use, invalidate the old one

## Architecture Patterns Reference

### Backend Layer Responsibilities

```
Route (app/api/routes/)      → HTTP concerns: parse request, validate input, return response
Service (app/services/)      → Business logic: orchestrate operations, enforce rules
Repository (app/repositories/) → Data access: SQL queries, ORM operations
Model (app/models/)          → Schema definition: tables, columns, constraints
Schema (app/schemas/)        → API contracts: Pydantic request/response models
Integration (app/integrations/) → External services: AI, email, SMS, price data
Job (app/jobs/)              → Background tasks: Celery workers, scheduled jobs
```

### External Service Integration Pattern

```python
# app/integrations/email/protocol.py
from typing import Protocol

class EmailProvider(Protocol):
    async def send(self, to: str, subject: str, body: str) -> bool: ...

# app/integrations/email/resend_adapter.py
class ResendAdapter:
    async def send(self, to: str, subject: str, body: str) -> bool:
        # Resend API call
        ...

# app/core/deps.py — wire via DI
def get_email_provider() -> EmailProvider:
    if settings.EMAIL_PROVIDER == "resend":
        return ResendAdapter(api_key=settings.RESEND_API_KEY)
    ...
```

### Frontend Route Groups

```
app/
  (public)/    → SSG/ISR pages, no auth required (leaderboard, profiles, stocks)
  (auth)/      → Login/register pages
  (user)/      → Authenticated user pages (dashboard, watchlist, submissions)
  (admin)/     → Admin/moderator pages (review queue, user management)
```
